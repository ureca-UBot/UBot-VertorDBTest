# 실험 설계

현재 기준은 [fairness-sweep-v2](fairness-v2.md)입니다. [2026-09-13 완료 결과](../07-results/fairness-v2-results-20260913.md)는 합성 10k·1024차원·concurrency 10에서 14개 구성 × 5회 독립 재구축, 124개 검색 설정 × 5회 = **620개 실측 점**입니다. 검색 파라미터 그리드 전체의 산포도를 읽어 Recall이 비슷한 설정끼리 지연·처리량·자원을 비교하며 자동 승자를 정하지 않습니다.

프로젝트의 예상 운영 규모는 **1,000~10,000청크**입니다. 현재 실측은 이 범위 상단의 합성 10k이고, 1k와 실제 서비스 입력의 측정은 아직 없습니다. 100k/1M은 성장 시 선택하는 확장 실험이지 지금 단계의 필수 통과 조건이 아닙니다. [2026-09-11의 372점](../07-results/sweep-results-20260911.md)은 별도 역사 실험으로 보존합니다.

```text
전체 재구축 반복 5회
  회차별 DB 순서 교차
    각 인덱스 구성
      DB 시작 및 자원 제한 검증
      drop → create → vector load → index ready
      그리드의 각 검색 파라미터 (회차 시드로 순서를 섞음)
        파라미터 적용 → evaluation warm-up
        evaluation measurement
        원시 점 저장 → CSV·집계·산포도 갱신
      DB 중지
```

매회 같은 그리드를 사용합니다. 인덱스 준비 시간과 적재 시간은 같은 재구축을 공유하는 모든 파라미터 행에 기록합니다. 이를 합산해 전체 구축 비용으로 해석하지 않습니다.

기본 300개 query는 기존 SHA-256 층화 분할을 유지합니다. evaluation 200개는 각 파라미터의 워밍업과 측정에 사용합니다. calibration 100개는 Milvus 추가 진단용이며 파라미터를 선택하거나 제외하는 데 쓰지 않습니다. 두 집합의 ID 해시를 저장합니다.

기본 부하는 Top-10, concurrency 10입니다. 워밍업은 같은 동시성으로 200질의 단위를 최소 3회, 최대 10회 실행하고 최근 3회 p95의 변동 폭을 확인합니다. 본 측정은 evaluation 200개 × measurementIterations 5, 즉 1,000요청 단위를 최소 30초·검색 구간 내 자원 표본 30개를 모두 충족하도록 반복합니다. `measurementIterations=5`는 독립 재구축 5회와 다릅니다. QPS 타이머는 모든 검색 작업이 끝날 때 닫고 Recall 계산·응답 검증·저장을 제외합니다.

Recall 0.90과 0.95에 도달하더라도 나머지 그리드를 계속 측정합니다. 단조성 보정, 허용 범위 검사, 목표별 대표 후보 선택을 실행 경로에 적용하지 않습니다. 과거 fixed-target 방식의 calibration 선택과 목표 ±0.01 규칙은 이번 sweep의 선택 정책이 아닙니다. 평가 grid를 사후에 보고 후보를 고르면 탐색 선택이므로, 같은 평가 질의로 독립 최종 검증을 했다고 주장하지 않습니다.

집계는 같은 생성·검색 설정과 데이터·부하 조건끼리 수행합니다. 각 지표의 평균, median, p95/p99, min/max, 표본분산을 원시 반복값과 함께 보존합니다. 원시 산포도는 **620개 실제 점**을 사용하고, 5회 집계 산포도는 **124개 설정의 median p95/QPS·Recall 평균/범위**를 명시한 별도 보조 그림으로 읽습니다. 두 종류의 점을 혼동하거나 유리한 회차만 대표로 고르지 않습니다.

Milvus 진단은 본 측정 후 별도 calibration 질의에서 직렬·동시성 검색을 각각 3회 수행합니다. 첫 동시성 표본 대비 편차와 두 모드 median 차이, 상태 수집 결과를 기록하지만 측정 도중의 재현성을 보증하지는 않습니다. 이번 DISKANN 5개 측정에서는 동일 질의의 측정 중 Recall 변동이 확인돼 별도 확인 대상으로 남깁니다. 워밍업 불안정 170점도 경고와 함께 보존합니다.

RAM은 관측 비교 지표입니다. 현재 `DecisionGate`의 RAM 2GiB·p95 30ms 기본값은 합의된 서비스 SLO가 아니므로 이 문서의 구성 탈락 기준으로 사용하지 않습니다. 코드와 기존 summary의 판정은 아직 그대로이며, 판정 미사용을 코드 수정 완료로 읽으면 안 됩니다.

추가 검증은 실제 프로젝트의 1k~10k 청크·질의·필터 분포부터 별도로 설계합니다. 필터 선택도 1%/10%/50%, 새로운 holdout, 필요 시 100k/1M 확장은 서로 다른 검증 축입니다. 별도 입력이 없는 결과를 기존 10k로 대신하거나 미실시를 DB 실패로 표시하지 않습니다.
